# 濒危植物种子萌发试验封存台

这是面向植物保护实验员、种质库管理员和科研质量复核员的本地治理工作台。系统把种源建档、萌发试验设计、分阶段观测、阈值异常裁决、同行复核、整改和不可变封存凭据串成一条可追溯流程。服务使用 Go 原生 HTTP 提供响应式 HTML 页面和同源 JSON API，数据保存在带哈希链的 JSON Lines 事件日志中，重启后自动重放恢复。

## 构建、运行与测试

```text
go build ./...
go run ./cmd/seedvault -addr=127.0.0.1:19081
go test ./...
```

默认监听 `127.0.0.1:19081`。可以使用 `-addr=127.0.0.1:<port>` 指定回环地址，也可以设置 `PORT` 端口号；服务不会默认监听外部网卡。数据目录默认为 `data`，可用 `-data` 调整。

## 自检

下面的命令启动临时服务并自行完成完整业务链路，成功后退出：

```text
go run ./cmd/seedvault -selfcheck -addr=127.0.0.1:19081
```

浏览器打开服务地址即可使用“总览”“种源建档”“试验设计”和“观测与治理”页面。API 路径以 `/api/` 开头，凭据可以通过 `/api/certificates/{id}/verify` 验证。

## 业务完整性

批次编码会在去除首尾空白并统一大小写后执行全库唯一校验，停用或封存的种源不能创建试验。试验设计支持“第 N 天”和 `YYYY-MM-DD` 时间点，创建时固化计划观测矩阵并拦截同一种源的活动设计冲突。

观测入口既兼容单条记录，也支持同一阶段的 `Observations` 数组；整批只提交一个试验版本，任一行无效则整批不写入。同一次观测产生的异常可通过 `Decisions` 数组合并裁决。退回复核使用 `RemediationItems` 整改清单，证据入口通过 `RemediationItemID` 逐项闭环。

冻结前系统检查所有阶段与重复组坐标、未裁决异常、未完成整改以及最新复核结论。验证接口分别返回快照哈希、审计链头、凭据状态和冻结版本结论，重复冻结返回原凭据。
